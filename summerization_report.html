Omni-Qwen vs. Cascaded Summarization Pipeline

Model Architectures

Omni-Qwen

Layer 1: Audio Encoder
OpenAI Whisper Base Encoder processing 16kHz mono waveforms. Mel-spectrogramming, Conv2D downsampling.

Layer 2: Speech Projector
EncoderProjectorConcat reduces dimensionality. Groups frames and maps to LLM hidden size. ~6.6M params.

Layer 3: Speech-Text LLM
Qwen2.5-0.5B-Instruct. Speech embeddings are concatenated directly with text tokens in the forward pass. ~2.0M Trainable LoRA Params.

Traditional Cascaded Pipeline

Step 1: ASR (Audio to Text)
Input audio is processed by standard Whisper to generate a raw intermediate transcript. Subject to standard WER errors.

Step 2: LLM Summarization
The raw transcript string is fed as a text prompt into an independent text model (BERT, FLAN-T5, or Qwen).

Trade-offs:
Loss of acoustic context (tone, prosody) at the text boundary. ASR hallucination errors propagate heavily into the final LLM summary.

Evaluation Metrics

ROUGE F1 Scores: Measures n-gram overlap. R1 = unigrams, R2 = bigrams, RL = longest common subsequence.

Semantic Similarity: Cosine similarity of Sentence-BERT embeddings. sim = (v_pred · v_ref) / (||v_pred|| × ||v_ref||)

Compression Performed (%): Percentage of the original word count that was reduced/removed. (1 - length(pred)/length(ref)) × 100. Ideal target reduction is ~50%.
